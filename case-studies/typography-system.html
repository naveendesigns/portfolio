Building a
Scalable Typography System.

Turning inconsistent typography into a minimal token-based system that designers and developers can use consistently.

FocusDesign tokens
ToolsFigma + CSS
PrincipleMinimal + flexible

Why it mattered

An audit of existing screens showed inconsistent font sizes, line heights and weights. That inconsistency made screens harder to maintain and made the relationship between Figma styles and production code unclear.

Building the scale

  • Audited existing screens and typography usage.
  • Compared established systems including Material Design and Tailwind.
  • Mapped the product to a minimal type scale instead of creating a large collection of one-off styles.
  • Defined font sizes, line heights and weights as reusable design tokens.
  • Set up Figma variables and global CSS custom properties.
  • Created a clear Figma-to-code mapping for developers.

Designing for implementation

A design system is only useful when the system survives the handoff.

I treated the implementation model as part of the design work. Tokens were named and structured so the same decision could be understood in Figma and expressed directly in CSS.

Learning

The project reinforced that good systems reduce decisions rather than adding more rules. A small, flexible scale created more consistency while keeping enough range for the product.
